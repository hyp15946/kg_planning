# Vercel 배포 가이드

정적 HTML 한 개다. 빌드도, 환경변수도, 서버도 없다.
**배포 자체는 5분이고, 나머지는 구글 설정이다.**

## 순서

```
1. Vercel 에 리포 연결   ← Root Directory 를 deploy 로 지정하는 것이 핵심
2. 배포 도메인 확인
3. 그 도메인을 OAuth 클라이언트에 등록
4. 드라이브 폴더를 팀에 공유
5. 각자 클라이언트 ID 를 한 번 넣고 로그인
```

3번까지 안 하면 사이트는 뜨지만 **로그인이 안 된다.**

---

## 1. Vercel 에 리포 연결

[vercel.com](https://vercel.com) → **Add New → Project** → 이 리포 선택(**Import**).

설정 화면에서 **한 가지만** 바꾼다.

| 항목 | 값 |
|---|---|
| **Root Directory** | **`deploy`** ← 반드시 바꾼다 |
| Framework Preset | `Other` (자동으로 잡힌다) |
| Build Command | **비워 둔다** |
| Output Directory | **비워 둔다** |
| Install Command | **비워 둔다** |
| Environment Variables | **없다** |

`index.html` 이 리포 루트가 아니라 `deploy/` 안에 있다.
Root Directory 를 안 바꾸면 배포는 성공하는데 **404** 가 뜬다.

> Root Directory 는 나중에도 바꿀 수 있다 — **Settings → Build and Deployment →
> Root Directory**. 바꾼 뒤 재배포해야 반영된다.

**Deploy** 를 누른다. 빌드가 없으므로 20초 안에 끝난다.

## 2. 배포 도메인 확인

`https://<프로젝트명>.vercel.app` 형태의 주소가 나온다. 이 주소를 열면
**「사내 전용」 로그인 화면**이 떠야 한다. 여기까지 왔으면 배포는 끝났다.

「클라이언트 ID 미설정」이라고 떠 있는 것이 정상이다. 3번을 하고 5번에서 넣는다.

> **Preview 배포 주소는 매번 바뀐다.** Vercel 은 커밋마다
> `<프로젝트>-<해시>-<팀>.vercel.app` 을 새로 만든다. 그 주소는 OAuth 에 등록되어 있지
> 않으므로 로그인이 안 된다 (`redirect_uri_mismatch`).
> **로그인 테스트는 항상 고정된 Production 주소에서 한다.**

사내 도메인을 붙이려면 **Settings → Domains** 에서 추가한다.
그 경우 3번에 **그 도메인도 함께** 등록해야 한다.

## 3. 배포 도메인을 OAuth 클라이언트에 등록

[console.cloud.google.com/auth/clients](https://console.cloud.google.com/auth/clients)
→ 만들어 둔 클라이언트 → 아래 두 개를 **추가**한다 (기존 localhost 항목은 지우지 않는다).

| 항목 | 값 |
|---|---|
| 승인된 JavaScript 원본 | `https://<배포-도메인>` |
| 승인된 리디렉션 URI | `https://<배포-도메인>/` |

**리디렉션 URI 는 끝의 `/` 까지 정확히 맞아야 한다.** 직접 타이핑하지 말고,
배포된 사이트의 **「설정」** 안에 표시된 값의 **「복사」** 버튼을 쓴다.
사이트가 자기 주소로 만든 값이므로 그것이 정답이다.

> 반영에 **5분에서 몇 시간**까지 걸린다. 바로 안 되면 기다렸다 다시 해본다.
> 급하게 여러 번 고치면 무엇이 문제였는지 알 수 없게 된다.

아직 안 했다면 `OAUTH_SETUP.md` 의 2·4·5번도 확인한다 —
**Slides API + Drive API 사용 설정**, **Audience 를 «내부»**, **스코프 4개**.

## 4. 드라이브 폴더를 팀에 공유

`개발 볼륨 산출 데이터` 폴더를 쓸 사람들에게 공유한다 (**보기 권한이면 충분**).

**공유되지 않은 계정은 로그인해도 데이터를 못 받는다.** 그것이 의도된 동작이다 —
접근 통제를 드라이브 권한이 하고 있다. 자세한 내용은 `README.md` 의 「접근 통제」.

## 5. 각자 클라이언트 ID 넣고 로그인

배포 주소 → **「설정」** → 클라이언트 ID 붙여넣기 → **저장** → **구글 계정으로 로그인**.

**클라이언트 ID 는 리포에 넣지 않는다.** 사내 채널로 공유하고 각자 한 번 넣는다.
번거롭지만 의도한 것이다 — 이유는 `OAUTH_SETUP.md` 7번
「클라이언트 ID 를 리포에 넣지 않는다」에 적혀 있다.

로그인하면 기준 데이터를 드라이브에서 자동으로 받아 산출 화면으로 들어간다.

## 배포 뒤 확인할 것

| 확인 | 정상 |
|---|---|
| 배포 주소를 연다 | 「사내 전용」 로그인 화면 |
| 「설정」을 연다 | 리디렉션 URI 가 `https://<배포-도메인>/` 로 표시 |
| 사내 계정으로 로그인 | 산출 화면 진입 + 헤더에 본인 이메일 |
| 「데이터」를 연다 | `드라이브 — projects.json · 폴더 「개발 볼륨 산출 데이터」 · 수정 …` |
| 사외 계정으로 로그인 | 화면이 잠기고 「@kiglestudio.com 계정으로 로그인하세요」 |

## 데이터를 갱신할 때

**배포를 다시 하지 않는다.** 드라이브의 `projects.json` 을 덮어쓰면 끝이다.
데이터는 탭을 닫으면 사라지고 다시 열 때 드라이브에서 새로 받으므로,
사용자는 다음 접속에 최신값을 본다.

지금 열려 있는 탭에서 바로 확인하려면 **「데이터」 → 「드라이브에서 다시 불러오기」**.

## 안 될 때

| 증상 | 원인 |
|---|---|
| **404** | Root Directory 가 `deploy` 가 아니다 (1번) |
| `redirect_uri_mismatch` | 배포 도메인을 등록하지 않았거나, Preview 주소로 접속했다 (2·3번) |
| `origin_mismatch` | 승인된 JavaScript 원본을 안 넣었다 (3번) |
| `access_denied` | Audience 가 「외부」다. 「내부」로 바꾼다 |
| 로그인은 되는데 **「기준 데이터 없음」** | 폴더가 그 계정에 공유되지 않았다 (4번), 또는 Drive API 미설정 |
| **「권한 범위가 부족합니다」** | 스코프를 늘리기 전에 받은 토큰이다. 「연결 해제」 후 다시 로그인 |
| 맞게 했는데도 안 된다 | 구글 설정 반영에 최대 몇 시간. 기다렸다 재시도 |

나머지 오류는 `OAUTH_SETUP.md` 의 「자주 나는 오류」에 정리되어 있다.

## 로컬에서 확인하려면

`file://` 로 열면 OAuth 가 **동작하지 않는다.** 반드시 서버로 띄운다.

```bash
python -m http.server 8000 --directory deploy
```

`http://localhost:8000/` 로 연다. `localhost` 는 HTTPS 가 아니어도 되지만,
**배포 도메인은 반드시 HTTPS** 여야 한다 (Vercel 은 자동으로 HTTPS다).
