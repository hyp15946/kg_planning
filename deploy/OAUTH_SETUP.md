# 구글 계정 연결 설정

사이트가 **기준 데이터(`projects.json`)와 기획서 슬라이드를 직접 읽기** 위한 설정.
**서버도 클라이언트 시크릿도 필요 없다.**

로그인은 두 가지를 겸한다.

| | 하는 일 |
|---|---|
| 접근 통제 | `@kiglestudio.com` 계정만 사이트를 쓸 수 있다 |
| 데이터 읽기 | 드라이브의 `projects.json` 과 기획서 슬라이드를 본인 권한으로 읽는다 |

> **메뉴 위치가 바뀌었다.** 예전에는 「API 및 서비스 → 사용자 인증 정보」였는데,
> 지금은 **「Google Auth Platform」** 이라는 별도 섹션으로 옮겨졌다.
> 옛날 안내 글을 보고 따라가면 메뉴가 없어서 막힌다.
>
> 헤매지 말고 이 주소로 바로 가면 된다 → **https://console.cloud.google.com/auth/clients**

## 전체 순서

```
1. 프로젝트 만들기
2. Slides API + Drive API 켜기
3. Google Auth Platform 등록  ← 이걸 먼저 해야 클라이언트를 만들 수 있다
4. Audience(대상)를 «내부»로   ← 사외 계정을 막는 핵심
5. Data access(데이터 액세스)에 스코프 4개 추가
6. Clients(클라이언트)에서 OAuth 클라이언트 만들기   ← 막히셨던 지점
7. 사이트에 클라이언트 ID 넣기
8. 드라이브에 projects.json 올리고 팀에 공유
```

**3번이 함정이다.** 앱 등록을 안 한 상태로 Clients 페이지에 가면 「CREATE CLIENT」 대신
등록 화면이 먼저 뜬다. 그래서 「사용자 인증 정보 만들기」 메뉴를 아무리 찾아도 안 보인다.

---

## 1. 프로젝트 만들기

[console.cloud.google.com](https://console.cloud.google.com) → 상단 프로젝트 선택기 → **새 프로젝트**.
이름은 아무거나 (예: `kigle-plan-db`). 결제 설정은 필요 없다.

만든 뒤 **상단에서 그 프로젝트가 선택돼 있는지 확인**한다. 다른 프로젝트에 만들어 놓고
못 찾는 경우가 흔하다.

## 2. Slides API + Drive API 켜기

왼쪽 메뉴 **「API 및 서비스」 → 「라이브러리」** → 아래 **둘 다** 검색해서 **사용 설정**.

| API | 쓰는 곳 |
|---|---|
| `Google Slides API` | 기획서 슬라이드에서 단계 목록 추출 |
| `Google Drive API` | 기준 데이터 `projects.json` 읽기 |

> 한쪽만 켜면 그 기능만 안 된다. 데이터는 뜨는데 기획서를 못 읽거나, 반대로
> 기획서는 읽히는데 「기준 데이터 없음」에서 멈춘다.
> 사이트가 `... has not been used ...` 라고 알려주니 그때 나머지를 켜면 된다.

## 3. Google Auth Platform 등록

왼쪽 메뉴에서 **「Google Auth Platform」** 을 찾는다. 안 보이면 메뉴 상단 검색창에
`Google Auth Platform` 을 치거나 https://console.cloud.google.com/auth/overview 로 간다.

하위 항목이 다섯 개다.

| 항목 | 하는 일 |
|---|---|
| Overview (개요) | 앱 등록 |
| Branding (브랜딩) | 앱 이름·지원 이메일·승인된 도메인 |
| **Audience (대상)** | 내부 / 외부 — 예전의 「User Type」 |
| **Clients (클라이언트)** | **OAuth 클라이언트 만들기 — 예전의 「사용자 인증 정보」** |
| Data access (데이터 액세스) | 스코프 — 예전의 「범위 추가」 |

「시작하기」가 뜨면 눌러서 등록을 마친다. 물어보는 건 앱 이름, 지원 이메일, 대상(내부/외부),
연락처 이메일 정도다.

## 4. Audience(대상) — 반드시 «내부» ★

**Audience** → User type을 **「내부 (Internal)」** 로.

**이것이 사외 계정을 막는 실제 장치다.** 내부로 하면 **kiglestudio.com 계정만** 로그인할 수 있고
**구글 심사를 안 받아도 된다.** 외부로 하면 심사를 받거나 테스트 사용자를 한 명씩 등록해야 하고,
등록 안 된 계정은 `access_denied` 가 난다.

사이트도 로그인한 계정의 도메인을 확인해 다른 도메인이면 화면을 잠근다. 다만 그것은
**브라우저에서 도는 안내**이고, 코드를 고치면 통과된다. 진짜로 막는 것은 이 «내부» 설정과
드라이브 파일 공유 권한 두 가지다. 배포물에 데이터가 없으므로 통과해도 볼 것이 없다.

> 회사 Workspace 계정으로 만든 프로젝트가 아니면 「내부」 선택지가 안 나온다.
> 개인 gmail로 로그인한 게 아닌지 확인한다.

## 5. Data access(데이터 액세스) — 스코프 4개

**Data access** → 「범위 추가 또는 삭제」 → 아래 네 개를 추가.

```
openid
email
https://www.googleapis.com/auth/presentations.readonly
https://www.googleapis.com/auth/drive.readonly
```

| 스코프 | 왜 필요한가 |
|---|---|
| `openid` · `email` | 로그인한 계정이 `@kiglestudio.com` 인지 확인 |
| `presentations.readonly` | 기획서 슬라이드 읽기 |
| `drive.readonly` | `projects.json` 을 이름으로 찾아서 읽기 |

모두 **읽기 전용**이다. 쓰기·삭제 권한은 요구하지 않는다.

> `drive.readonly` 는 그 계정 드라이브 **전체에 대한 읽기** 권한이다. 사이트는 `projects.json`
> 하나만 읽지만 권한 범위 자체는 넓다. 더 좁히려면 `drive.file` + Google Picker 로 바꿔야 하는데,
> 그러면 쓸 때마다 사람이 파일을 골라야 하고 API 키 관리가 따라온다.
> 사내 전용 도구라 여기서는 `drive.readonly` 를 택했다.

## 6. Clients — OAuth 클라이언트 만들기 ★

**Google Auth Platform → 「Clients (클라이언트)」** → 위쪽 **「+ CREATE CLIENT (클라이언트 만들기)」**

바로 가기: https://console.cloud.google.com/auth/clients

| 항목 | 값 |
|---|---|
| 애플리케이션 유형 | **웹 애플리케이션** |
| 이름 | 아무거나 (콘솔에서만 보인다) |
| 승인된 JavaScript 원본 | `https://<배포-도메인>` |
| 승인된 리디렉션 URI | **사이트가 화면에 표시하는 값을 그대로 복사** |

리디렉션 URI는 사이트의 **「드라이브에서 읽기 → 설정」** 안에 정확한 값이 적혀 있다.
직접 타이핑하지 말고 복사해 넣는다. 한 글자만 달라도 `redirect_uri_mismatch` 가 난다.

만들고 나면 `xxxxxxxx.apps.googleusercontent.com` 형태의 **클라이언트 ID** 가 나온다.
**클라이언트 시크릿은 안 쓴다.** 나와도 무시하면 된다 — 이 사이트는 PKCE 공개 클라이언트라
시크릿이 필요 없다. 그래서 리포가 공개여도 시크릿이 새어 나갈 일이 없다.

다만 **클라이언트 ID 는 리포에 넣지 않는다.** 시크릿은 아니지만, 공개 리포에 올리면
`localhost` 등록과 맞물려 문제가 된다 — 7번 참고.

> 설정 변경은 **5분에서 몇 시간까지** 반영이 걸릴 수 있다. 바로 안 되면 조금 기다렸다 다시 해본다.

### 로컬에서 테스트하려면

`file://` 로 열면 OAuth가 **동작하지 않는다.** 서버로 띄우고, 아래 두 개를 각각 등록한다.

- 승인된 JavaScript 원본: `http://localhost:8000`
- 승인된 리디렉션 URI: `http://localhost:8000/`

```
python -m http.server 8000
```

HTTPS가 아니어도 되는 건 localhost뿐이다. 배포 도메인은 반드시 HTTPS여야 한다.

## 7. 사이트에 클라이언트 ID 넣기

### ⚠ 먼저 — 사이트를 «서버로» 열어야 한다

`index.html` 을 탐색기에서 더블클릭해 여는 것(`file://`)으로는 **OAuth가 절대 동작하지 않는다.**
주소(origin)가 없어서 구글에 등록할 리디렉션 URI 자체가 만들어지지 않는다.
사이트가 이 상태를 감지하면 빨간 경고를 띄우고 「구글 계정 연결」 버튼을 잠근다.

**`index.html` 이 있는 폴더에서:**

```
python -m http.server 8000
```

그런 다음 브라우저에서 **http://localhost:8000/** 로 연다.
그러면 「설정」 안에 등록할 값 두 개가 실제 주소로 표시된다.

| | 값 |
|---|---|
| 승인된 JavaScript 원본 | `http://localhost:8000` |
| 승인된 리디렉션 URI | `http://localhost:8000/` |

이 둘을 6번에서 만든 클라이언트에 등록한다. 리디렉션 URI 옆 **「복사」** 버튼을 쓰면 정확하다.
배포한 뒤에는 배포 도메인으로 같은 두 값을 **한 번 더 추가**한다.
localhost 것은 지우지 말고 둘 다 두면 로컬·배포 양쪽에서 쓸 수 있다.

> 한 클라이언트에 localhost 를 남겨두는 편이 편해서 그대로 두지만, **그 대신 클라이언트 ID 를
> 리포에 올리면 안 된다.** 아래 「클라이언트 ID 를 리포에 넣지 않는다」 참고.

### 클라이언트 ID 입력

첫 화면(로그인 관문)의 **「설정」** → 클라이언트 ID 붙여넣기 → 저장.
브라우저에만 저장되고 리포·배포물에는 들어가지 않는다.
쓰는 사람마다 각자 한 번 넣는다. 번거롭지만 **의도한 것이다.**

### ⚠ 클라이언트 ID 를 리포에 넣지 않는다

`index.html` 에 기본값으로 박아 두면 편하지만 **하지 않는다.** 리포가 공개이기 때문이다.

클라이언트 ID 자체는 시크릿이 아니다. 로그인할 때 주소창에 그대로 보이므로 이 사이트를
쓰는 사람에게는 이미 노출되어 있고, 숨길 수도 없다. 그것만으로 토큰을 받아낼 수도 없다 —
리디렉션 URI 정확 일치, PKCE, 「내부」 대상, 드라이브 공유 권한이 각각 막는다.

**그런데 위 「로컬에서 테스트하려면」 대로 `localhost:8000` 을 같은 클라이언트에
등록해 두면 이야기가 달라진다.** ID가 인터넷에 공개된 상태에서 이런 경로가 열린다.

1. 누구든 공개 리포에서 클라이언트 ID를 읽는다
2. 직원 PC의 `localhost:8000` 에서 악성 페이지가 돌게 만든다
   (악성 npm 패키지의 dev 서버 등 — 포트만 잡으면 된다)
3. 그 페이지가 **우리 클라이언트 ID로** 자기 PKCE 검증자를 써서 로그인 흐름을 띄운다
4. `localhost:8000` 은 등록된 리디렉션이므로 code가 그 페이지로 간다
5. 토큰 교환 성공 → **그 직원 드라이브 전체 읽기 권한**을 얻는다

로컬 코드 실행이 전제라 문턱은 높다. 다만 스코프가 `drive.readonly`(드라이브 전체)라
대가가 크다. **ID를 리포에 올리지 않으면 1번이 성립하지 않아 이 경로 자체가 없어진다.**

ID는 사내 채널로 공유하고, 각자 「설정」에 한 번 넣는다.

> 굳이 코드에 박고 싶다면 **클라이언트를 두 개로 나눠야** 한다 — 배포용(배포 도메인만
> 등록, ID 공개 가능)과 로컬 개발용(`localhost` 등록, ID 비공개).
> 배포용에 `localhost` 가 없으면 위 경로가 닫힌다.

## 8. 드라이브에 projects.json 올리고 공유

사이트는 **파일 ID를 코드에 박지 않고 이름으로 찾는다.** 순서는 이렇다.

1. 드라이브에서 **`개발 볼륨 산출 데이터`** 라는 이름의 폴더를 찾는다
2. 그 폴더 안의 **`projects.json`** 을 찾는다
3. 못 찾으면 드라이브 전체에서 `projects.json` 을 이름으로 찾는다
4. 여러 개면 **가장 최근에 수정된 것**을 쓴다

그래서 해야 할 일은 두 개다.

- 폴더명을 **`개발 볼륨 산출 데이터`** 로, 파일명을 **`projects.json`** 으로 유지한다
- 그 폴더를 **쓸 사람들에게 공유**한다 (보기 권한이면 충분하다)

공유되지 않은 계정은 로그인해도 파일을 받지 못한다. **이것이 접근 통제의 두 번째 층이다.**

이름을 바꾸거나 다른 위치에 두고 싶으면, 관문의 **「설정 → 기준 데이터 파일」** 에
드라이브 링크나 파일 ID를 넣으면 그 파일만 쓴다 (브라우저에만 저장된다).
폴더·파일 이름 자체를 바꾸려면 `index.html` 상단의 `DATA_FOLDER` · `DATA_FILE` 을 고친다.

## 쓰는 방법

1. 사이트를 열면 **로그인 관문**이 먼저 뜬다 → **구글 계정으로 로그인**
2. 로그인하면 **기준 데이터를 드라이브에서 자동으로 불러온다** (파일을 따로 넣지 않는다)
3. 1번 항목의 **기획서 드라이브 링크** 채우기 (「과거 DB에서 링크 채우기」로 자동 입력 가능)
4. **기획서 읽기** → 슬라이드에서 번호 붙은 단계를 코드로 추출
5. **「2-1. 뽑아낸 단계 확인」** — 도식이 아닌 슬라이드를 제외하고 파트 키 지정
6. **이 단계 목록으로 산출하기**

토큰은 1시간짜리이고 탭 세션에만 저장된다. 만료되면 다시 로그인한다.
기준 데이터도 탭을 닫으면 사라지고 다시 열면 드라이브에서 새로 받는다 —
**스프레드시트가 갱신되면 `projects.json` 만 덮어쓰면 모두가 최신값을 본다.**

## 접근 통제가 어디서 일어나는가

REQUIREMENTS 3번이 「구글 계정 인증」을 보류한 이유는, *배포물 안에 들어 있는 데이터*를
클라이언트 코드만으로 지킬 수 없기 때문이었다. 그 판단은 지금도 맞다.

그래서 **데이터를 배포물에서 뺐다.** 데이터는 드라이브에 있고 각자의 토큰으로 읽는다.
그러면 지켜야 할 것이 배포물에 없으므로 서버 없이도 통제가 성립한다.

| 층 | 무엇이 막나 | 실제 강제력 |
|---|---|---|
| OAuth Audience «내부» | 사외 계정 로그인 | **있음** — 구글이 막는다 |
| 드라이브 파일 공유 권한 | 데이터 다운로드 | **있음** — 구글이 막는다 |
| 사이트의 도메인 확인 | 화면 표시 | **없음** — 안내용. 코드를 고치면 통과된다 |

세 번째 층은 «잘못된 계정으로 들어왔다»고 알려주기 위한 것이다. 이것만 믿어서는 안 되지만,
앞의 두 층이 실제로 막고 있고 통과해도 볼 데이터가 없으므로 문제가 되지 않는다.

**서버가 필요해지는 경우는 하나다** — 배포물 자체에 데이터를 담아야 할 때. 그때는
REQUIREMENTS 3번의 판단이 그대로 돌아온다.

## 왜 시크릿이 필요 없는가

*본인 드라이브를 본인 대신 읽는* 것이고, OAuth 공개 클라이언트(Public Client)의
정식 용도다. PKCE를 쓰면 시크릿 없이 안전하게 토큰을 받는다.
그래서 리포가 공개여도 시크릿 걱정은 없다. **클라이언트 ID 는 별개 문제다** — 7번 참고.

## 자주 나는 오류

| 오류 | 원인 |
|---|---|
| **Clients 페이지에 만들기 버튼이 없다** | 3번(앱 등록)을 안 했다. 등록부터 마친다 |
| **왼쪽 메뉴에 「사용자 인증 정보」가 없다** | 「Google Auth Platform → Clients」로 옮겨졌다 |
| **「로컬 파일 — 로그인 불가」가 뜬다** | `file://` 로 열었다. `python -m http.server 8000` 후 `http://localhost:8000/` |
| **리디렉션 URI 칸이 「(없음)」이다** | 같은 원인. 서버로 띄우면 실제 주소가 표시된다 |
| **「…으로는 사용할 수 없습니다」** | `@kiglestudio.com` 아닌 계정으로 로그인했다 |
| **「…폴더의 projects.json 을 찾지 못했습니다」** | 폴더·파일 이름이 다르거나, 그 계정에 공유되지 않았다. 8번 참고 |
| `redirect_uri_mismatch` | 등록한 URI가 사이트 표시값과 다르다. 화면 값을 그대로 복사 |
| `origin_mismatch` | 승인된 JavaScript 원본을 안 넣었다 |
| `access_denied` | 대상이 「외부」인데 테스트 사용자 미등록. 「내부」로 바꾼다 |
| `Google Slides API has not been used...` | 2번에서 Slides API를 안 켰다 |
| `Google Drive API has not been used...` | 2번에서 Drive API를 안 켰다 |
| **「권한 범위가 부족합니다」** | 스코프를 늘리기 전에 승인한 토큰이다. 「연결 해제」 후 다시 로그인 |
| `The caller does not have permission` | 그 기획서(또는 데이터 파일)에 권한이 없는 계정으로 로그인했다 |
| 로그인 버튼을 눌러도 아무 일 없음 | `file://` 로 열었다. 서버로 띄운다 |
| 설정을 맞췄는데도 안 된다 | 반영에 최대 몇 시간 걸린다. 기다렸다 재시도 |

## 도식이 그림 파일이면

Slides API는 텍스트와 도형만 준다. 도식이 이미지로 붙어 있으면 단계가 0개로 나온다.
기획서 양식상 그럴 일은 없지만, 만약 그렇다면 「2-1」 화면의 **슬라이드 원문 텍스트**를 보고
직접 단계를 적거나 `steps.json` 을 만들어 「steps.json 불러오기」로 넣는다.
형식은 `STEPS_SCHEMA.md` 참고.

## 나중에 서버를 붙이고 싶다면

`GAuth` 객체 하나만 교체하면 된다. 다만 재로그인이 귀찮다는 이유만으로 서버를 붙이는 건
권하지 않는다 — 클라이언트 시크릿과 환경변수 관리가 따라오고,
REQUIREMENTS 3번이 그걸 보류한 이유가 그대로 적용된다.
