# 구글 계정 연결 설정

기획서 슬라이드를 사이트가 직접 읽기 위한 설정. **서버도 클라이언트 시크릿도 필요 없다.**

> **메뉴 위치가 바뀌었다.** 예전에는 「API 및 서비스 → 사용자 인증 정보」였는데,
> 지금은 **「Google Auth Platform」** 이라는 별도 섹션으로 옮겨졌다.
> 옛날 안내 글을 보고 따라가면 메뉴가 없어서 막힌다.
>
> 헤매지 말고 이 주소로 바로 가면 된다 → **https://console.cloud.google.com/auth/clients**

## 전체 순서

```
1. 프로젝트 만들기
2. Slides API 켜기
3. Google Auth Platform 등록  ← 이걸 먼저 해야 클라이언트를 만들 수 있다
4. Audience(대상)를 «내부»로
5. Data access(데이터 액세스)에 스코프 추가
6. Clients(클라이언트)에서 OAuth 클라이언트 만들기   ← 막히셨던 지점
7. 사이트에 클라이언트 ID 넣기
```

**3번이 함정이다.** 앱 등록을 안 한 상태로 Clients 페이지에 가면 「CREATE CLIENT」 대신
등록 화면이 먼저 뜬다. 그래서 「사용자 인증 정보 만들기」 메뉴를 아무리 찾아도 안 보인다.

---

## 1. 프로젝트 만들기

[console.cloud.google.com](https://console.cloud.google.com) → 상단 프로젝트 선택기 → **새 프로젝트**.
이름은 아무거나 (예: `kigle-plan-db`). 결제 설정은 필요 없다.

만든 뒤 **상단에서 그 프로젝트가 선택돼 있는지 확인**한다. 다른 프로젝트에 만들어 놓고
못 찾는 경우가 흔하다.

## 2. Slides API 켜기

왼쪽 메뉴 **「API 및 서비스」 → 「라이브러리」** → `Google Slides API` 검색 → **사용 설정**.

Drive API는 켜지 않는다. 프레젠테이션 ID로 Slides API만 부르므로 필요 없다.

## 3. Google Auth Platform 등록

왼쪽 메뉴에서 **「Google Auth Platform」** 을 찾는다. 안 보이면 메뉴 상단 검색창에
`Google Auth Platform` 을 치거나 https://console.cloud.google.com/auth/overview 로 간다.

하위 항목이 다섯 개다.

| 항목 | 하는 일 |
|---|---|
| Overview (개요) | 앱 등록 |
| Branding (브랜딩) | 앱 이름·지원 이메일·승인된 도메인 |
| **Audience (대상)** | 내부 / 외부 — 예전의 「User Type」 |
| **Clients (클라이언트)** | **OAuth 클라이언트 만들기 — 예전의 「사용자 인증 정보」** |
| Data access (데이터 액세스) | 스코프 — 예전의 「범위 추가」 |

「시작하기」가 뜨면 눌러서 등록을 마친다. 물어보는 건 앱 이름, 지원 이메일, 대상(내부/외부),
연락처 이메일 정도다.

## 4. Audience(대상) — 반드시 «내부»

**Audience** → User type을 **「내부 (Internal)」** 로.

이게 중요하다. 내부로 하면 **kiglestudio.com 계정만** 쓸 수 있고 **구글 심사를 안 받아도 된다.**
외부로 하면 심사를 받거나 테스트 사용자를 한 명씩 등록해야 하고, 등록 안 된 계정은
`access_denied` 가 난다.

> 회사 Workspace 계정으로 만든 프로젝트가 아니면 「내부」 선택지가 안 나온다.
> 개인 gmail로 로그인한 게 아닌지 확인한다.

## 5. Data access(데이터 액세스) — 스코프 하나만

**Data access** → 「범위 추가 또는 삭제」 → 아래 하나만 추가.

```
https://www.googleapis.com/auth/presentations.readonly
```

읽기 전용이고 프레젠테이션에만 해당한다. 드라이브 전체 권한은 요구하지 않는다.

## 6. Clients — OAuth 클라이언트 만들기 ★

**Google Auth Platform → 「Clients (클라이언트)」** → 위쪽 **「+ CREATE CLIENT (클라이언트 만들기)」**

바로 가기: https://console.cloud.google.com/auth/clients

| 항목 | 값 |
|---|---|
| 애플리케이션 유형 | **웹 애플리케이션** |
| 이름 | 아무거나 (콘솔에서만 보인다) |
| 승인된 JavaScript 원본 | `https://<배포-도메인>` |
| 승인된 리디렉션 URI | **사이트가 화면에 표시하는 값을 그대로 복사** |

리디렉션 URI는 사이트의 **「드라이브에서 읽기 → 설정」** 안에 정확한 값이 적혀 있다.
직접 타이핑하지 말고 복사해 넣는다. 한 글자만 달라도 `redirect_uri_mismatch` 가 난다.

만들고 나면 `xxxxxxxx.apps.googleusercontent.com` 형태의 **클라이언트 ID** 가 나온다.
**클라이언트 시크릿은 안 쓴다.** 나와도 무시하면 된다 — 이 사이트는 PKCE 공개 클라이언트라
시크릿이 필요 없고, 그래서 리포가 공개여도 문제가 없다.

> 설정 변경은 **5분에서 몇 시간까지** 반영이 걸릴 수 있다. 바로 안 되면 조금 기다렸다 다시 해본다.

### 로컬에서 테스트하려면

`file://` 로 열면 OAuth가 **동작하지 않는다.** 서버로 띄우고, 아래 두 개를 각각 등록한다.

- 승인된 JavaScript 원본: `http://localhost:8000`
- 승인된 리디렉션 URI: `http://localhost:8000/`

```
python -m http.server 8000
```

HTTPS가 아니어도 되는 건 localhost뿐이다. 배포 도메인은 반드시 HTTPS여야 한다.

## 7. 사이트에 클라이언트 ID 넣기

### ⚠ 먼저 — 사이트를 «서버로» 열어야 한다

`index.html` 을 탐색기에서 더블클릭해 여는 것(`file://`)으로는 **OAuth가 절대 동작하지 않는다.**
주소(origin)가 없어서 구글에 등록할 리디렉션 URI 자체가 만들어지지 않는다.
사이트가 이 상태를 감지하면 빨간 경고를 띄우고 「구글 계정 연결」 버튼을 잠근다.

**`index.html` 이 있는 폴더에서:**

```
python -m http.server 8000
```

그런 다음 브라우저에서 **http://localhost:8000/** 로 연다.
그러면 「설정」 안에 등록할 값 두 개가 실제 주소로 표시된다.

| | 값 |
|---|---|
| 승인된 JavaScript 원본 | `http://localhost:8000` |
| 승인된 리디렉션 URI | `http://localhost:8000/` |

이 둘을 6번에서 만든 클라이언트에 등록한다. 리디렉션 URI 옆 **「복사」** 버튼을 쓰면 정확하다.
배포한 뒤에는 배포 도메인으로 같은 두 값을 **한 번 더 추가**한다.
localhost 것은 지우지 말고 둘 다 두면 로컬·배포 양쪽에서 쓸 수 있다.

> 기준 데이터(`projects.json`)는 `file://` 로도 잘 불러와진다. **데이터가 뜬다고 OAuth도 될 거라고
> 보면 안 된다.** 둘은 별개다.

### 클라이언트 ID 입력

「드라이브에서 읽기 → 설정」 → 클라이언트 ID 붙여넣기 → 저장.
브라우저에만 저장되고 리포·배포물에는 들어가지 않는다.

---

## 쓰는 방법

1. **구글 계정 연결** → 로그인 → 사이트로 돌아옴
2. 1번 항목의 **기획서 드라이브 링크** 채우기 (「과거 DB에서 링크 채우기」로 자동 입력 가능)
3. **기획서 읽기** → 슬라이드에서 번호 붙은 단계를 코드로 추출
4. **「2-1. 뽑아낸 단계 확인」** — 도식이 아닌 슬라이드를 제외하고 파트 키 지정
5. **이 단계 목록으로 산출하기**

토큰은 1시간짜리이고 탭 세션에만 저장된다. 만료되면 「구글 계정 연결」을 한 번 더 누른다.

## 왜 시크릿이 필요 없는가

REQUIREMENTS 3번의 「보류: 구글 계정 인증」은 *데이터를 남에게서 지키는* 문제였다.
그건 클라이언트만으로 안 되고 서버 검증이 필요하다.

여기는 다르다. *본인 드라이브를 본인 대신 읽는* 것이고, OAuth 공개 클라이언트(Public Client)의
정식 용도다. PKCE를 쓰면 시크릿 없이 안전하게 토큰을 받는다.

| | 3번의 인증 (보류) | 여기의 인증 |
|---|---|---|
| 목적 | 배포물 안의 데이터 접근 통제 | 사용자 드라이브 읽기 대행 |
| 서버 | 필요 | **불필요** |
| 클라이언트 시크릿 | 필요 | **불필요 (PKCE)** |
| 공개 리포 | 주의 | 무관 |

## 자주 나는 오류

| 오류 | 원인 |
|---|---|
| **Clients 페이지에 만들기 버튼이 없다** | 3번(앱 등록)을 안 했다. 등록부터 마친다 |
| **왼쪽 메뉴에 「사용자 인증 정보」가 없다** | 「Google Auth Platform → Clients」로 옮겨졌다 |
| **「로컬 파일로 열림 — 연결 불가」가 뜬다** | `file://` 로 열었다. `python -m http.server 8000` 후 `http://localhost:8000/` |
| **리디렉션 URI 칸이 「(없음)」이다** | 같은 원인. 서버로 띄우면 실제 주소가 표시된다 |
| `redirect_uri_mismatch` | 등록한 URI가 사이트 표시값과 다르다. 화면 값을 그대로 복사 |
| `origin_mismatch` | 승인된 JavaScript 원본을 안 넣었다 |
| `access_denied` | 대상이 「외부」인데 테스트 사용자 미등록. 「내부」로 바꾼다 |
| `Google Slides API has not been used...` | 2번을 건너뛰었다 |
| `The caller does not have permission` | 그 기획서에 권한이 없는 계정으로 로그인했다 |
| 연결 버튼을 눌러도 아무 일 없음 | `file://` 로 열었다. 서버로 띄운다 |
| 설정을 맞췄는데도 안 된다 | 반영에 최대 몇 시간 걸린다. 기다렸다 재시도 |

## 도식이 그림 파일이면

Slides API는 텍스트와 도형만 준다. 도식이 이미지로 붙어 있으면 단계가 0개로 나온다.
기획서 양식상 그럴 일은 없지만, 만약 그렇다면 「2-1」 화면의 **슬라이드 원문 텍스트**를 보고
직접 단계를 적거나 `steps.json` 을 만들어 「steps.json 불러오기」로 넣는다.
형식은 `STEPS_SCHEMA.md` 참고.

## 나중에 서버를 붙이고 싶다면

`GAuth` 객체 하나만 교체하면 된다. 다만 재로그인이 귀찮다는 이유만으로 서버를 붙이는 건
권하지 않는다 — 클라이언트 시크릿과 환경변수 관리가 따라오고,
REQUIREMENTS 3번이 그걸 보류한 이유가 그대로 적용된다.
