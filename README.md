# 기획 볼륨 산출

기획서의 단계 목록에서 파트별 **개발 볼륨 / 디자인 볼륨**을 산출한다.
`[키글] 앱 종합 스케쥴` 의 볼륨 칸에 넣을 값이 최종 산출물이다.

**→ https://kg-planning.vercel.app** (`@kiglestudio.com` 계정 전용)

## 쓰는 법

1. 사이트를 연다 → **`@kiglestudio.com` 계정으로 로그인**
2. 기준 데이터는 **드라이브에서 자동으로 불러온다** (따로 넣지 않는다)
3. **1. 기획서** — 프로젝트명 · 러프/상세 · 드라이브 링크
4. **2. 단계 목록** — 「드라이브에서 읽기」로 슬라이드에서 뽑거나 `steps.json` 을 불러온다
5. **2-1** 에서 단계 수를 먼저 확인하고 파트 키를 지정
6. **3~5** 등급 확정 · 디자인 가산 · 부대 항목
7. **6. 산출 결과** — 스케쥴 문서에 옮기고, 필요하면 JSON/CSV로 내보낸다

## 이 리포에 없는 것

**데이터는 리포에 넣지 않는다.** 리포가 공개이기 때문이다.

| 파일 | 어디에 있나 |
|---|---|
| `projects.json` | 드라이브 **`개발 볼륨 산출 데이터`** 폴더. 사이트가 이름으로 찾아 읽는다 |
| 기획서 링크 목록 | 위 파일 안에 들어 있다 |
| 추출한 단계 목록 | 각자 로컬 |

## 접근 통제

`@kiglestudio.com` 계정만 쓸 수 있다. **막는 것은 구글이고, 사이트가 아니다.**

| 층 | 실제 강제력 |
|---|---|
| OAuth Audience «내부» — 사외 계정 로그인 차단 | **있음** |
| 드라이브 파일 공유 권한 — 데이터 다운로드 차단 | **있음** |
| 사이트의 도메인 확인 — 화면 잠금 | 없음 (안내용) |

세 번째는 잘못된 계정으로 들어왔을 때 알려주기 위한 것이고, 코드를 고치면 통과된다.
**배포물에 데이터가 없으므로 통과해도 볼 것이 없다.** 지키는 일은 앞의 두 층이 한다.

데이터는 탭이 열려 있는 동안만 브라우저에 남고 탭을 닫으면 사라진다.
그래서 `projects.json` 을 덮어쓰면 모두가 다음 접속에 최신값을 본다.

## 구조

Next.js **정적 내보내기**(`output: "export"`)다. 서버가 없고 빌드 결과는 정적 파일뿐이다.

```
app/       page.tsx — 화면 상태를 여기서 들고 있다
components/  화면 조각 (구획별로 하나씩)
lib/       계산·인증·드라이브 — DOM 을 모른다
```

| 파일 | 내용 |
|---|---|
| `lib/volume.ts` | **볼륨 계산 (순수 함수)** — `volume.test.ts` 로 검증 |
| `lib/slides.ts` | 슬라이드 → 단계 후보 파싱 — `slides.test.ts` 로 검증 |
| `lib/gauth.ts` | 구글 OAuth (PKCE) · 로그인 계정 도메인 확인 |
| `lib/drive.ts` | 드라이브에서 `projects.json` 찾기·받기 |
| `lib/datasource.ts` | 기준 데이터 로딩 · 세션 보관 |
| `lib/config.ts` | `ALLOWED_DOMAIN` · `DATA_FOLDER` · `DATA_FILE` · 스코프 |
| `DEPLOY.md` | Vercel 배포 절차 |
| `OAUTH_SETUP.md` | 구글 설정 (로그인 · 드라이브 · 슬라이드) |
| `STEPS_SCHEMA.md` | `steps.json` 형식 |

계산 로직은 `lib/` 에 순수 함수로 있고 화면과 섞이지 않는다. 등급 규칙을 고칠 때는
`lib/volume.ts` 와 그 테스트만 보면 된다.

찾을 위치나 허용 도메인을 바꾸려면 `lib/config.ts` 를 고친다.

> ⚠ `next.config.ts` 의 `output: "export"` 를 지우지 않는다. 서버가 생기는 순간
> «배포물에 지킬 데이터가 없다» 는 위 접근 통제의 전제가 무너진다.

## 개발

```bash
npm install
npm run dev        # http://localhost:8000
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 (8000 포트 — OAuth 리디렉션 등록값과 맞춘 값) |
| `npm test` | 계산·파싱 로직 테스트 |
| `npm run typecheck` | 타입 검사 |
| `npm run lint` | 린트 |
| `npm run build` | `out/` 에 정적 파일 생성 |

`file://` 로 열면 OAuth 가 동작하지 않는다. 반드시 `npm run dev` 로 띄운다.

## 계산 방식

- **개발 볼륨 = 단계 단위 합산.** 게임 단위로 뭉개면 크게 과소 산정된다
- **디자인 볼륨 = 파트 단위 가산.** 등급표가 원래 파트 단위 가산 규칙이다
- **합산은 코드가 한다.** 단계별 등급과 근거를 함께 내보내 검산할 수 있다
- **소요일·개월은 계산하지 않는다.** 스케쥴 문서가 자동으로 계산한다

등급 후보가 둘 이상이면 하나를 고르지 않는다. 둘 다 띄우고 **기본값 없이 미정으로** 남기며,
미정인 단계는 합계에 들어가지 않는다.

## 배포

GitHub → Vercel. Next.js 를 자동으로 알아본다. **환경변수는 없다.**
**절차는 `DEPLOY.md`**, 구글 설정은 `OAUTH_SETUP.md`.

놓치기 쉬운 것 세 개만 적어 둔다.

- 배포 도메인을 **배포용** OAuth 클라이언트의 **승인된 JavaScript 원본**과
  **승인된 리디렉션 URI**에 등록한다. 안 하면 사이트는 떠도 로그인이 안 된다
- **Preview 배포 주소로는 로그인이 안 된다.** 커밋마다 주소가 바뀌어 OAuth 에 등록돼 있지
  않기 때문이다. 로그인 테스트는 고정된 Production 주소에서 한다
- ❌ **배포용 클라이언트에 `localhost` 를 추가하지 않는다.** 아래 참고

## 클라이언트 ID 를 두 개로 나눈 이유

쓰는 사람이 아무것도 입력하지 않도록 **배포용 클라이언트 ID 를 `lib/config.ts` 에 넣어 두었다.**
공개 리포에 올라가지만, 클라이언트 ID 는 시크릿이 아니다 — 로그인할 때 주소창에 그대로 보인다.

**위험은 «공개된 ID» + «등록된 localhost» 조합에서만 생긴다.** 그 조합이면 직원 PC 의
`localhost` 에서 도는 악성 페이지가 우리 ID 로 로그인 흐름을 띄워 **그 사람 드라이브 전체
읽기 토큰**을 받아낼 수 있다.

| | 배포용 | 로컬 개발용 |
|---|---|---|
| 등록된 리디렉션 | 배포 도메인만 | `localhost:8000` |
| ID 를 리포에 두는가 | **둔다** (`lib/config.ts`) | **안 둔다** |
| 넣는 곳 | 코드 | 「개발자 설정」 (브라우저에만 저장) |

나눠 두면 공개된 ID 에는 localhost 가 없고, localhost 가 있는 ID 는 공개되지 않아
그 경로가 닫힌다. **배포용에 localhost 를 추가하면 나눈 의미가 없어진다** —
자세한 내용은 `OAUTH_SETUP.md` 7번.
